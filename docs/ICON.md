# DeepTally icon

Visual identity for DeepTally: the app icon, the menu bar glyph and the README hero.
Every file below is generated by one deterministic script — nothing is hand-painted, nothing is
downloaded, and no third-party tool is used.

| File | Size | Purpose |
|---|---|---|
| `Scripts/make-icon.swift` | — | generator (AppKit + CoreGraphics only) |
| `Resources/AppIcon.icns` | 1024² + all smaller reps | app icon, copied into `DeepTally.app/Contents/Resources/` by `Scripts/bundle.sh` |
| `Resources/MenuBarIconTemplate.png` | 16×16 | status item glyph |
| `Resources/MenuBarIconTemplate@2x.png` | 32×32 | status item glyph (Retina) |
| `docs/assets/hero.png` | 1200×400 | README hero |

`dist/icon/AppIcon.iconset/` (git-ignored) is the intermediate iconset; it is regenerated on every run.

## Design

**Layered squircle.** The body is a superellipse — |x/a|⁵ + |y/b|⁵ = 1 — not a rounded rectangle, so
the corners come out with continuous curvature the way Apple's own icon grid does. It occupies
824×824 of a 1024×1024 canvas (100 px transparent margin), the proportions of Apple's macOS app icon
grid. Inside sit a second inset squircle panel (752×752), a soft drop shadow and a dark hairline rim.

**Depth gradient + glass.** The body runs indigo → navy → deep teal top to bottom (depth = deeper =
darker). A teal radial glow sits behind the dial, a white wash fades down from the top edge, a second
highlight opens the top-left corner, and a dark gradient grounds the base. That is the "one sheet of
glass over a gradient" look of the Golden Gate design language, built from four gradients.

**Centered gauge.** A 236° arc (track in pale teal at 34 %, filled value arc in teal) with a tapered
amber needle and a bright hub: measurement, and the needle's "how much is left" reading that a balance
meter implies. One warm accent only — the needle and hub are the only orange pixels in the icon.

## Why it reads at 16 px

- **Silhouette first.** At 16 px the body is 12.9 px wide with a 1.6 px transparent margin — a dark
  squircle on the Dock/menu bar. It is legible before any detail is.
- **Three shapes survive:** the teal arc (10.3 px outer width, 1.6 px thick), the amber needle
  (~1.3 px at its base) and the 2 px warm hub. They are the highest-contrast elements in the icon and
  they sit on the darkest part of the gradient.
- **Nothing is thinner than ~1.5 px at 16 px**, and there are no small glyphs, text or hairlines that
  would dissolve. The inner panel and rim exist only at ≥32 px.
- **Every size is rendered natively.** The script draws each iconset PNG at its target pixel size
  instead of resampling the 1024² master, so no size carries downscaling artefacts.

## Menu bar glyph

Three descending tally bars, 2 px tall with 2 px gaps on a 16×16 grid, aligned to whole pixels so the
16 px bitmap stays crisp (1 px corner radius = pill ends). Descending widths read as depth marks and
survive at 16 px in a way a dial would not.

Both files are **pure black + alpha**: the generator verifies every pixel is `R = G = B = 0` and exits
non-zero otherwise. macOS tints a template image, so the glyph draws black on a light menu bar and
white on a dark one. The `Template` suffix is the convention `NSImage(named:)` uses to set `isTemplate`;
when loading via `NSImage(contentsOf:)` set `isTemplate = true` explicitly.

## Hero

`docs/assets/hero.png` (1200×400) is a dark plate: the app icon at 300 px, the wordmark "DeepTally"
(SF Pro Bold 104 pt, "Deep" in near-white, "Tally" in teal) and the tagline
"DeepSeek balance · spend · cache-hit rate", with an amber accent rule under the wordmark. It is
generated by the same script so the hero and the icon can never drift apart.

## Regenerate

```sh
swift Scripts/make-icon.swift
```

The script writes every artefact and then verifies its own output: the ten iconset PNGs exist at
the right pixel sizes, both template PNGs are 16/32 px and pure black + alpha, the `.icns` starts with
the `icns` magic, and the hero is 1200×400 and not blank. Any mismatch exits non-zero. It runs
`/usr/bin/iconutil -c icns` itself.

Manual spot checks:

```sh
file Resources/AppIcon.icns
sips -g pixelWidth -g pixelHeight Resources/AppIcon.icns
sips -g pixelWidth -g pixelHeight -g hasAlpha Resources/MenuBarIconTemplate.png Resources/MenuBarIconTemplate@2x.png
iconutil -c iconset Resources/AppIcon.icns -o /tmp/AppIcon.iconset   # round-trip
```

Output is byte-identical across runs: no randomness, no timers, no network, no dates, and the same
input pixels always encode to the same PNG.

## Why the .icns is committed

`actool` is unavailable — it ships with Xcode, and this machine has Command Line Tools only. The CLT
**does** provide `/usr/bin/iconutil` and `/usr/bin/sips`, so the icon is built locally and the result
is committed: no `.xcassets`, and `Scripts/bundle.sh` simply copies `Resources/AppIcon.icns` into the
app bundle (the `CFBundleIconFile` key is already `AppIcon`). Regenerating is a rebuild-free,
one-command operation for anyone with the CLT — the committed file exists so that a plain
`make bundle` never depends on running the generator first.
